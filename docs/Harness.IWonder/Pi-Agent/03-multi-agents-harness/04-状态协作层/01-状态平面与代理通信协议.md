# 状态平面与代理通信协议

> [!abstract]
> 多代理协作的稳定性取决于独立于聊天上下文的状态平面：Task Registry 保存业务责任，Run Registry 保存执行事实，Evidence Store 保存可验证结论，Artifact Store 保存大型成果，Mailbox 保存协调消息；Agent 通过结构化命令和事件引用这些事实，Lead 只在里程碑与阻塞发生时被唤醒。

> [!note]
> **上层主题：** [任务、运行与会话生命周期](../03-生命周期控制层/01-任务运行与会话生命周期.md)  
> **下层主题：** [有界证据侦察代理](../05-侦察代理产品原型层/01-有界证据侦察代理.md)

## 1. 状态平面的职责

状态平面提供：

- 单一事实源；
- 崩溃恢复；
- 并发控制；
- 任务依赖；
- Evidence Provenance；
- Artifact 发现；
- 消息去重；
- 审计与重放。

聊天上下文只是一种消费视图，不能承担权威状态。

## 2. Task Registry

### 2.1 Task Record

```ts
interface TaskRecord {
  taskId: string;
  contractVersion: number;
  status: TaskStatus;
  role: AgentRole;
  dependencies: string[];
  owner?: string;
  leaseExpiresAt?: number;
  activeRunId?: string;
  deliverables: ArtifactRef[];
  verification?: VerificationResult;
}
```

### 2.2 Task Registry 不变量

- Task ID 全局稳定；
- Dependency 必须构成无环图；
- 未满足依赖的 Task 不进入 Ready；
- 写 Task 同时只允许一个有效 Lease；
- Completed 必须引用 Deliverable；
- Verified 必须引用 Verification Result。

## 3. Run Registry

### 3.1 Run Record

```ts
interface RunRecord {
  runId: string;
  taskId: string;
  contractVersion: number;
  role: AgentRole;
  phase: RunPhase;
  version: number;
  budget: BudgetSnapshot;
  progress: ProgressSnapshot;
  lastHeartbeatAt?: number;
  lastProgressAt?: number;
  businessStatus?: BusinessTerminalStatus;
  infrastructureStatus?: InfrastructureStatus;
  finalArtifact?: ArtifactRef;
}
```

### 3.2 Runtime Handle 分离

Process、AgentSession、RPC Client 与 AbortController 存放在内存 Handle Map，不进入 Durable Run Record。

```text
Durable RunRecord
  ↕ run_id
Ephemeral RunHandle
  ├─ AgentSession
  ├─ ChildProcess
  ├─ RpcClient
  ├─ AbortController
  └─ unsubscribe
```

## 4. Evidence Store

### 4.1 Evidence Record

```ts
interface EvidenceRecord {
  evidenceId: string;
  taskId: string;
  runId: string;
  questionIds: string[];
  claim: string;
  kind: "lead" | "verified" | "contradicted";
  path: string;
  lineStart: number;
  lineEnd: number;
  excerpt: string;
  confidence: "low" | "medium" | "high";
  contentHash?: string;
  validation: "pending" | "accepted" | "rejected";
}
```

### 4.2 Evidence Validation

Validator 检查：

- Path 位于 Scope；
- Line Range 有效；
- Excerpt 与文件内容一致；
- Question ID 存在；
- Claim 与已有 Evidence 非重复；
- Content Hash 对应读取时版本。

模型负责语义判断，Runtime 负责引用真实性。

### 4.3 Evidence 与 Observation

Observation 是一次探索结果，Evidence 是被接受的事实记录。

```text
Tool Result
  ↓
Observation
  ├─ accepted evidence
  ├─ useful lead
  └─ low-yield outcome
```

## 5. Artifact Store

### 5.1 Artifact 类型

- Scout Report；
- Evidence Table；
- Call Chain；
- Implementation Plan；
- Patch 或 Diff；
- Test Log；
- Review Findings；
- Verification Result；
- Known Risk Record。

### 5.2 Artifact Reference

```ts
interface ArtifactRef {
  artifactId: string;
  type: string;
  path: string;
  summary: string;
  producerRunId: string;
  contentHash: string;
  createdAt: number;
}
```

大型内容通过 Path 与 Hash 传递，消息只携带摘要与引用。

## 6. Mailbox

### 6.1 Message 类型

- Blocked Notice；
- Scope Change Request；
- Budget Extension Request；
- Evidence Milestone；
- Dependency Ready；
- Peer Challenge；
- Verification Failure；
- Run Completed。

### 6.2 Message Envelope

```ts
interface MailboxMessage {
  messageId: string;
  taskId: string;
  runId?: string;
  from: string;
  to: string;
  kind: string;
  sequence: number;
  causationId?: string;
  payload: unknown;
  createdAt: number;
  acknowledgedAt?: number;
}
```

### 6.3 消息纪律

- 消息只传协调意图；
- 大型内容只传 Artifact Reference；
- 每条消息拥有稳定 ID；
- Receiver 显式 Ack；
- 重复 Delivery 幂等处理；
- Terminated Run 的迟到消息进入审计而不改状态。

## 7. Event Protocol

### 7.1 Event Envelope

```ts
interface HarnessEvent {
  eventId: string;
  taskId: string;
  runId: string;
  sequence: number;
  type: HarnessEventType;
  causationId?: string;
  timestamp: number;
  payload: unknown;
}
```

### 7.2 Telemetry Event

不进入 Lead Context：

- Tool Started；
- Tool Completed；
- Token Usage；
- Heartbeat；
- Raw Stream Delta；
- Internal Retry。

### 7.3 Milestone Event

可合并后通知 Lead：

- Question Answered；
- Evidence Added；
- Scope Drift Detected；
- Budget Near Limit；
- Blocked；
- Finalization Requested；
- Run Completed；
- Infrastructure Failed。

### 7.4 Event Replay

- Producer 按 Run 递增 Sequence；
- Consumer 保存 Last Seen Sequence；
- 重连后从下一 Sequence 重放；
- 重复 Event 不重复执行 Mutation；
- Sequence Gap 触发 Snapshot Refresh。

## 8. Pi 通信映射

### 8.1 同进程 SDK

```text
AgentSession.subscribe
  → Harness Event Adapter
  → Run Registry
  → Milestone Aggregator
  → pi.sendMessage to Lead
```

控制使用：

- `session.steer()`；
- `session.followUp()`；
- `session.abort()`。

### 8.2 RPC Child

```text
Lead Extension
  ↔ RPC stdin/stdout
Child Pi Runtime
```

RPC Command 负责控制，Agent Event 负责观察，Extension Command 可修改 Child 内部 Policy State。

### 8.3 `pi.events`

`pi.events` 适合同进程 Extension 协作；它不跨 OS Process，不能替代 RPC、IPC 或 Durable Mailbox。

### 8.4 Lead Context 注入

`pi.sendMessage()` 只用于高价值事件：

```json
{
  "kind": "BUDGET_NEAR_LIMIT",
  "run_id": "run-scout-auth-01",
  "remaining_calls": 2,
  "unresolved_questions": ["default-consistency"]
}
```

普通 Telemetry 只更新 UI、Run Snapshot 或外部日志。

## 9. Claim、Lease 与 Heartbeat

### 9.1 Claim

Agent 在执行写 Task 前获得 Claim；Claim 记录 Owner、时间与 Contract Version。

### 9.2 Lease

Lease 防止崩溃 Agent 永久占用 Task：

```text
CLAIMED
  ├─ heartbeat renews lease
  └─ lease expires → READY / REASSIGN
```

### 9.3 Last Progress

Heartbeat 证明存活，Last Progress 证明有效推进；二者必须分离。

- Heartbeat 更新但无进展可能表示发散；
- 无 Heartbeat 表示 Runtime 失联；
- 有 Evidence 增量更新 Last Progress；
- Lead 可基于 Last Progress 请求 Finalize。

## 10. 状态一致性规则

- Mutation 携带 `expected_version`；
- Command 携带 `command_id`；
- Event 携带 `sequence`；
- Artifact 携带 `content_hash`；
- Evidence 携带 Provenance；
- Lease 携带 Expiry；
- 所有 Terminal Transition 不可逆；
- Audit Event 采用 Append-only。

## 11. 状态面设计决策

- Task List 管进度。
- Run Registry 管执行。
- Evidence Store 管事实。
- Artifact Store 管成果。
- Mailbox 管协调。
- Git 与 Worktree 管版本。
- Conversation 只提供人类可读叙事。
