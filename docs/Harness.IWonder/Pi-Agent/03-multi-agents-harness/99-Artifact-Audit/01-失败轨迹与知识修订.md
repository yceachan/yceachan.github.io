# 多代理失败轨迹与知识修订

> [!abstract]
> 两次社区多代理实践表明，模型能够完成局部编码并不意味着工作流能够交付：上游侦察结果未被下游接受、各角色重复缴纳上下文重建成本、实现满足检查后仍继续探索、Reviewer 越过 Diff 与验收范围、最终缺少 E2E 和 Commit；这些事实要求知识库从“隔离、结构化交付和生命周期控制”继续推进到“Context Capsule、Artifact Acceptance、Completion Latch、Verification Authority 与 Failure Salvage”。

## 1. 经验材料的证据地位

这份 Artifact 记录两次真实失败轨迹：

- Pi 与社区 `pi-subagents` 的异步 Workflow；
- Pi 与 `pi-intercom` 的多 Session 协作；
- Scout、Researcher、Worker 与 Reviewer 的 Turn、Context 与时长；
- 实现、测试、审查、E2E 与 Git 集成状态；
- 用户主动 Abort 与人工收尾。

它是失败机制的案例证据，不是多代理效率的统计基准；两次案例足以否定若干过强假设，但不足以证明所有多代理系统必然更慢。

## 2. 两条轨迹的共同模式

| 阶段 | 可观察事实 | 系统缺口 |
| :-- | :-- | :-- |
| 发现 | Scout 与 Researcher 长时间继续探索 | Scope、查询与停止门禁不足 |
| 交接 | 后续角色重新读取同一背景 | 上游 Artifact 未形成接受协议 |
| 实现 | 检查通过后仍继续搜索 | Completion Latch 缺失 |
| 验证 | LSP 假错误引发重复修正 | Verification Authority 缺失 |
| 审查 | Reviewer 越过 Diff 和 Package 范围 | Review Scope Gate 缺失 |
| 集成 | 缺少 Live E2E 与 Commit | Deliverable 与 Integration Gate 不完整 |
| 编排 | Workflow 标记失败但局部成果可用 | Failure Salvage 缺失 |
| 通信 | 多 Session 能互发消息但无法收敛 | Transport 被误当作 Harness |

## 3. 多代理净收益模型

原有 Parallelism Value 需要加入上下文与交接成本：

```text
Multi-Agent Net Value
  = Independent Work Value
  + Independent Perspective Value
  - Context Reacquisition Cost
  - Artifact Conversion Cost
  - Coordination Cost
  - Duplicate Verification Cost
  - Integration Cost
  - File Conflict Risk
```

当上游 Artifact 没有被下游采用时，Context Isolation Benefit 不能计入收益，而应转化为 Context Reacquisition Cost。

## 4. 上下文隔离的修订模型

### 4.1 四个对齐边界

```text
Cognitive Boundary
  Agent 知道什么

Responsibility Boundary
  Agent 应该完成什么

State Boundary
  Agent 实际能够修改什么

Acceptance Boundary
  哪些证据允许该角色停止
```

任一边界缺失都会抵消隔离收益：

- 只隔离认知会产生重复调查；
- 只隔离权限会产生责任空白；
- 只共享状态会产生写入冲突；
- 缺少验收边界会产生持续探索。

### 4.2 选择性共享

始终共享：

- Objective；
- Task Contract；
- Acceptance Contract；
- 冻结设计决策；
- Verified Facts；
- Dependency Artifact；
- 当前状态变化。

默认隔离：

- 原始推理过程；
- 无关日志；
- 被否定探索路径；
- 其他角色局部噪音。

延迟共享：

- 可能锚定独立 Reviewer 的候选结论；
- 竞争方案的偏好；
- 尚未验证的根因假设。

## 5. Context Capsule

Scout Report 需要升级为可消费的 Context Capsule：

```ts
interface ContextCapsule {
  artifactId: string;
  taskId: string;
  contractVersion: number;
  sourceScope: ScopeSnapshot;
  filesRead: FileRef[];
  verifiedClaims: EvidenceRef[];
  rejectedHypotheses: EvidenceRef[];
  decisions: DecisionRef[];
  constraints: ConstraintRef[];
  unresolvedGaps: ContextGap[];
  confidence: "low" | "medium" | "high";
  contentHash: string;
  verification: "pending" | "verified" | "rejected";
}
```

Context Capsule 解决三个问题：

- 来源是否可信；
- 覆盖范围是否足够；
- 下游还需要补充什么。

## 6. Artifact Acceptance Protocol

### 6.1 Handoff ACK

下游 Agent 启动后先提交：

```yaml
handoff_ack:
  accepted_artifacts:
    - scout-context-v1
  accepted_claims:
    - extension-entry
    - pi-exec-contract
    - test-pattern
  rejected_claims: []
  context_gaps:
    - live-codex-imagegen-flags
  permitted_additional_reads:
    - codex-cli-help
```

### 6.2 Context Gap Gate

下游扩大读取前必须关联：

- 未满足 Question；
- Acceptance Criterion；
- Evidence Gap；
- 新发现 P0/P1；
- Artifact Verification 失败。

无法关联时记为 Scope Drift 或 Duplicate Recon。

### 6.3 Role-specific Trust

- Worker 默认接受 Verified Context Capsule；
- Planner 只基于 Verified Claims 规划；
- Reviewer 可以抽样复核但不重做全量 Recon；
- 独立 Reviewer 可延迟接收候选根因以避免锚定。

## 7. Completion Latch

### 7.1 满足条件

```text
Required Files Exist
AND Required Tests Pass
AND Required Typechecks Pass
AND Required Documentation Exists
AND Remaining Gaps Classified
  ↓
RUN SATISFIED
```

### 7.2 Latch 行为

进入 Satisfied 后：

- 停止普通探索；
- 只允许缺失 E2E；
- 只允许 Commit；
- 只允许 Final Report；
- 额外探索需要 Lead 解锁。

### 7.3 Completion Latch 与 Finalizing

`SATISFIED` 是触发条件，`FINALIZING` 是执行阶段：

```text
RUNNING
  ↓ acceptance satisfied
SATISFIED
  ↓ automatic latch
FINALIZING
  ↓ artifact + commit + report
TERMINATED
```

## 8. Verification Authority

### 8.1 权威检查层级

```text
Level 1  Focused Tests
Level 2  Package Typecheck
Level 3  Root Typecheck
Level 4  Packaging and Manifest Checks
Level 5  Live E2E
```

辅助信号：

- LSP Diagnostics；
- Editor Warning；
- Symlinked Dependency Warning；
- Non-authoritative Static Hint。

### 8.2 冲突处理

权威检查通过而辅助信号冲突时：

1. 记录 Environment Anomaly；
2. 禁止重复修改已通过代码；
3. 必要时请求 Lead Arbitration；
4. 不把单一辅助警告升级为无限修复循环。

## 9. Reviewer Scope Gate

Reviewer 默认 Scope：

```text
Changed Files
+ Directly Affected Interfaces
+ Acceptance-required Tests
+ Declared Packaging Artifacts
```

扩大范围必须提交：

```yaml
review_scope_request:
  path: workspace-lockfile
  reason: manifest introduced dependency changes
  criterion: PACKAGE-DEPENDENCY-01
  expected_value: detect inconsistent dependency state
```

无法关联 Criterion 或 P0/P1 的外围发现只能进入 Advisory 或 Follow-up。

## 10. Integration Deliverable

实现类 Task 的正式 Deliverable 包含：

```yaml
deliverables:
  - implementation_diff
  - focused_test_result
  - package_typecheck_result
  - root_typecheck_result
  - live_e2e_result_or_blocker
  - reviewed_commit
```

缺少 Commit 时只能进入：

```text
IMPLEMENTED_NOT_INTEGRATED
```

缺少 Live E2E 时必须记录：

- 阻塞原因；
- 可执行命令；
- 所需外部条件；
- 当前替代验证证据。

## 11. Workflow Failure Salvage

Workflow Failure 不抹平成功 Stage：

```ts
interface WorkflowFailureReport {
  completedArtifacts: ArtifactRef[];
  verifiedArtifacts: ArtifactRef[];
  interruptedRuns: RunRef[];
  missingDeliverables: string[];
  integrationState: string;
  recoveryActions: RecoveryAction[];
}
```

Lead 可以：

- Collect 已完成 Artifact；
- Abort 发散 Child；
- 补做缺失验证；
- 从最近 Verified Artifact 恢复；
- 接受局部成果并拆分 Follow-up。

## 12. 协作效率指标

### 12.1 Context Reacquisition Ratio

```text
Repeated File Reads Across Roles
────────────────────────────────

```

### 12.2 Artifact Reuse Ratio

```text
Artifacts ACKed by Downstream
─────────────────────────────
Artifacts Produced Upstream
```

### 12.3 Exploration After Satisfaction

```text
Exploration Calls After Acceptance Satisfied
```

### 12.4 Review Scope Drift

```text
Reviewer Reads Outside Declared Scope
─────────────────────────────────────
All Reviewer Reads
```

### 12.5 Integration Completion Rate

```text
Tasks with Reviewed Commit
──────────────────────────
Tasks with Workspace Changes
```

### 12.6 Context Tax

Context Tax 同时记录：

- 重复文件读取；
- 重复搜索 Query；
- 重复测试运行；
- 下游未接受 Artifact；
- Acceptance 满足后的额外 Turn。

## 13. 既有定论审阅

| 既有定论 | 审阅 | 修订 |
| :-- | :-- | :-- |
| 独立 AgentSession 带来上下文隔离收益 | 片面 | 只有 Verified Context 可复用时才产生净收益 |
| Structured Report 足以完成交接 | 过时 | 需要 Context Capsule、Verification 与 Handoff ACK |
| 每 Turn 只允许一个探索动作 | 过度约束 | 改为有界探索批次与批次级 Observation Commit |
| Start/Status/Control/Collect 足以监督 | 片面 | 增加 Handoff、Acceptance、Completion Latch 与 Salvage |
| Artifact Path 与摘要足以共享事实 | 片面 | 增加 Coverage、Provenance、Verification 与 Acceptance State |
| Completed、Verified、Integrated 三段完成语义 | 仍有效 | 增加 Run-level SATISFIED 与 IMPLEMENTED_NOT_INTEGRATED |
| Reviewer 只依据冻结 Acceptance | 仍有效但不足 | 增加 Diff Scope 与 Scope Expansion Request |
| RPC/IPC 提供协作基础 | 容易误读 | Transport 只负责通信，不提供协调与验收 |
| 高能力模型会改善多代理效果 | 片面 | 高思考可能放大继续探索偏差 |
| 单 Package 单入口角色路由 | 实现选项 | 不应提升为 Harness 不变量 |

## 14. 保留的核心定论

以下结论继续成立：

- Raw Runtime Context 不暴露给 Agent；
- Prompt 不替代 Runtime Policy；
- Active Tools 不替代 Extension 隔离；
- Conversation 不作为权威状态；
- Unknown 是合法结论；
- Budget Exhausted 先 Finalize 后 Abort；
- Agent Completed 不等于 Task Verified；
- Reviewer 不修改冻结 Acceptance；
- Lead 只依据结构化状态宣告全局终态。

## 15. 修订后的主链

```text
Role-isolated Runtime
  ↓
Task and Acceptance Contract
  ↓
Bounded Execution
  ↓
Verified Context Capsule
  ↓
Downstream Handoff ACK
  ↓
Context Gap-controlled Exploration
  ↓
Completion Latch
  ↓
Authoritative Verification
  ↓
Reviewed Commit / Integration Artifact
  ↓
Lead Convergence or Failure Salvage
```

## 16. 新增工程主张

- Context Isolation 必须与 Artifact Reuse 成对设计。
- Handoff 必须包含下游接受动作。
- Exploration 必须在 Acceptance 满足后自动上锁。
- Verification Signal 必须具有权威层级。
- Commit 与 E2E 状态必须进入正式 Deliverable。
- Workflow Failure 必须保全可复用局部成果。
- 多代理评估必须测量 Context Tax。
- Transport、Coordination 与 Governance 必须分层。
