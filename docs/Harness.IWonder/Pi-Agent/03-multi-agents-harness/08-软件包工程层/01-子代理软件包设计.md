# 子代理软件包设计

> [!abstract]
> `pi-subagents` 应采用单 Package、多内部角色模块、按 Runtime Role 条件装配的结构：Lead Runtime 只暴露调度 Capability，Scout、Planner、Worker 与 Reviewer Runtime 只加载本角色 Extension、Skills 与 Tools，共享生命周期、状态与治理内核；Package 负责分发，ResourceLoader 负责加载，AgentSession 负责隔离，Active Tools 负责最终模型可见面。

> [!note]
> **上层主题：** [子代理、团队与工作流](../07-多代理产品层/01-子代理团队与工作流.md)  
> **返回总览：** [多代理支撑系统知识树](../00-总览层/00-多代理支撑系统知识树.md)

## 1. 工程目标

Package 需要同时满足：

- 单次安装；
- Role Runtime 隔离；
- 最小 Agent Tool Surface；
- Hooks 按角色加载；
- Task 与 Run 状态可恢复；
- SDK 与 RPC Transport 可替换；
- Scout 原型可独立交付；
- Team 与 Workflow 可渐进扩展。

## 2. 边界模型

```text
Package
  负责代码与资源分发

Extension
  负责功能与 Hook 加载

ResourceLoader
  负责角色资源装配

AgentSession
  负责 Context 与运行隔离

Tool Registry
  负责 Runtime 已知能力

Active Tools
  负责模型可见能力
```

这些边界不能互相替代：

- Package 内有很多工具不等于 Agent 看见很多工具；
- Tool 未激活不等于 Extension Hook 未加载；
- AgentSession 隔离不等于 OS 权限隔离；
- Prompt 角色约束不等于 Runtime Policy。

## 4. 单入口角色路由

### 4.1 Package Manifest

Package 默认只暴露一个 Extension Entry：

```json
{
  "name": "pi-subagents",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./src/index.ts"],
    "skills": ["./skills"]
  }
}
```

### 4.2 Role Flag

```ts
export default function subagentsExtension(pi: ExtensionAPI) {
  pi.registerFlag("subagent-role", {
    description: "Internal role for a child runtime",
    type: "string",
  });

  const role = pi.getFlag("subagent-role");

  if (!role) {
    registerLeadRuntime(pi);
    return;
  }

  registerSharedPolicy(pi);
  registerRoleRuntime(pi, role);
}
```

### 4.3 Lead Runtime

只注册：

- `subagent_start`；
- `subagent_status`；
- `subagent_control`；
- `subagent_collect`；
- Supervisor Lifecycle Hooks；
- Milestone Notification Adapter。

### 4.4 Scout Runtime

只注册：

- Scope 与 Budget Hooks；
- Low-Yield State；
- `scout_search`；
- `scout_read`；
- `record_evidence`；
- `submit_scout_report`。

Scout Runtime 不注册 Lead 调度工具，避免递归启动与权限扩散。

## 5. Tool Surface 设计

### 5.1 Lead Surface

```text
subagent_start
subagent_status
subagent_control
subagent_collect
```

四个 Tool 分别承担 Create、Read、Update 与 Collect 语义，避免一个超大 Schema 充满互斥 Optional Field。

### 5.2 Scout Surface

```text
scout_search
scout_read
record_evidence
submit_scout_report
```

### 5.3 Planner Surface

```text
read
find
grep
submit_implementation_plan
```

### 5.4 Worker Surface

```text
read
edit
write
bash
run_verification
submit_work_result
```

### 5.5 Reviewer Surface

```text
read
grep
find
run_readonly_check
submit_review_verdict
```

## 6. Tool 注册策略

### 6.1 条件注册

优先只注册当前 Role 工具；该方式同时减少 Tool Registry、Hook 与副作用。

### 6.2 注册后激活

同一 Role 内存在渐进工具时，先注册全部专业工具，再只激活基础工具与 Tool Search。

### 6.3 不采用的模式

不在同一 Runtime 内注册所有角色再频繁切换角色；该模式会保留无关 Hooks、状态与 Prompt 语义。

## 7. Supervisor 内核

```ts
interface RunHandle {
  runId: string;
  record: RunRecord;
  transport: SubagentTransport;
  abortController: AbortController;
  unsubscribe?: () => void;
}

class SubagentSupervisor {
  start(contract: TaskContract): Promise<RunSnapshot>;
  status(runId: string): RunSnapshot;
  control(command: ControlCommand): Promise<RunSnapshot>;
  collect(runId: string, waitMs?: number): Promise<CollectResult>;
  shutdownAll(reason: string): Promise<void>;
}
```

Supervisor 负责：

- Run Handle；
- State Transition；
- Transport 生命周期；
- Budget Timer；
- Event Adapter；
- Milestone Aggregation；
- Finalization Deadline；
- Shutdown Cleanup。

## 8. Transport 抽象

```ts
interface SubagentTransport {
  start(prompt: string): Promise<void>;
  steer(message: string): Promise<void>;
  followUp(message: string): Promise<void>;
  abort(): Promise<void>;
  subscribe(listener: (event: TransportEvent) => void): () => void;
  dispose(): Promise<void>;
}
```

实现：

- `SdkAgentTransport`；
- `RpcProcessTransport`；
- 后续 `RemoteWorkerTransport`。

业务状态机不依赖具体 Transport。

## 9. Role Manifest

```ts
interface RoleManifest {
  name: "scout" | "planner" | "worker" | "reviewer";
  model?: string;
  thinkingLevel?: ThinkingLevel;
  extensionPaths: string[];
  skillPaths: string[];
  activeTools: string[];
  systemPrompt: string;
  contextPolicy: "minimal" | "project" | "inherit";
  sessionPolicy: "memory" | "persisted";
  transport: "sdk" | "rpc";
}
```

Role Manifest 是装配描述，不承担 Task Contract 业务事实。

## 10. 状态持久化

### 10.1 Session-local

使用 `pi.appendEntry()` 保存：

- Run Snapshot；
- Contract Revision；
- Artifact Reference；
- Last Event Sequence；
- Supervisor Display State。

### 10.2 Process-external

Team、Detached Run 与跨 Session Recovery 需要外部 Store：

```text
.pi/subagents/
  ├─ tasks.jsonl
  ├─ runs.jsonl
  ├─ mailbox.jsonl
  └─ artifacts/
```

存储采用 Append-only Event 与 Materialized Snapshot 组合。

## 11. 安全模型

- Project-local Role Definition 受 Project Trust 控制；
- Child 默认不加载项目 Extension；
- `--no-extensions` 后显式加载 Role Extension；
- `--no-skills` 后显式加载 Role Skill；
- Scout 不提供任意 Bash；
- Worker 写入受 Scope 与 Worktree 限制；
- Untrusted Package 仍需人工审查。

## 12. Scout MVP

### 12.1 必需能力

- Scout Contract Schema；
- Role ResourceLoader；
- Read-only Tool Surface；
- Evidence Store；
- Scope Guard；
- Budget Guard；
- Low-Yield Detector；
- Structured Final Report；
- Lead Start/Status/Control/Collect；
- SDK 或 RPC 单一 Transport。

### 12.2 MVP 验证

- Scout 无法调用 Write 与 Edit；
- Scope 外 Path 在 Tool 执行前被拒绝；
- 同 Turn 多探索被限制；
- Budget Exhausted 进入 Finalizing；
- Evidence Citation 可验证；
- Lead 可中途 Finalize 与 Abort；
- Session Shutdown 清理 Child；
- Terminated Run 可 Collect。

## 14. 工程决策

- 单 Package 分发多个内部角色。
- 单入口按 Role 条件注册模块。
- 每个 AgentSession 使用独立 ResourceLoader。
- 每个角色保持最小 Tool Surface。
- 隐藏 Policy Hook 不占用模型 Tool Schema。
- SDK 与 RPC 通过 Transport Interface 解耦。
- Durable State 与 Runtime Handle 分离。
- Scout MVP 先证明有界探索与可控终止。
