## 4. 核心概念关系

### 4.1 机制与产品

```text
Pi Extension 提供机制
  ↓
Harness 提供秩序
  ↓
Role Runtime 提供隔离
  ↓
Task Contract 提供边界
  ↓
Policy 提供约束
  ↓
State Plane 提供事实
  ↓
Verification 提供可信度
  ↓
Lead 提供收敛
```

### 4.2 运行边界

```text
Package
  └─ 分发边界
      Extension
        └─ 功能加载边界
            ResourceLoader
              └─ 角色装配边界
                  AgentSession
                    └─ 运行隔离边界
                        Active Tools
                          └─ 模型可见边界
```

### 4.3 生命周期关系

```text
Task
  └─ one or more Runs
      └─ one AgentSession or RPC Child per Run
```

### 4.4 状态关系

```text
Task Registry
  管业务责任

Run Registry
  管执行事实

Evidence Store
  管可验证结论

Artifact Store
  管大型成果

Mailbox
  管协调消息

Git / Worktree
  管版本与文件隔离
```

## 5. 全库设计主张

- Extension 负责机制。
- Harness 负责秩序。
- Contract 负责边界。
- Policy 负责强制。
- State 负责事实。
- Agent 负责判断。
- Tool 负责能力。
- Lead 负责收敛。
- Verification 负责可信度。
- Lifecycle 负责终止性。

## 6. 全库核心不变量

1. Raw Runtime Context 不暴露给 Agent。
2. 不同 Role 使用独立 ResourceLoader 与 AgentSession。
3. Active Tools 不替代 Extension 隔离。
4. Prompt 不替代 Runtime Policy。
5. Conversation 不作为权威状态。
6. Unknown 是合法结论。
7. Budget Exhausted 先 Finalize 后 Abort。
8. Agent Completed 不等于 Task Verified。
9. Reviewer 不修改冻结 Acceptance。
10. Lead 只依据结构化状态宣告全局终态。

## 7. 最小落地切口

首个可验证产品为 Bounded Scout：

```text
Lead creates Scout Contract
  ↓
Scout Runtime isolates context and tools
  ↓
Policy enforces scope and budgets
  ↓
Scout records evidence per question
  ↓
Low-yield or budget triggers finalization
  ↓
Structured report returns to Lead
  ↓
Verification accepts or rejects evidence
```

该原型同时验证 Pi Extension 支撑、Harness 控制面、状态面、治理面与生命周期协议，是后续 Planner、Worker、Reviewer、Team 和 Workflow 的共同基础。
